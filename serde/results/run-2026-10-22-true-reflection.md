# Прогон 2026-10-22 (вечер) — интерфейсное загрязнение найдено и вычищено

Два дефекта стенда найдены и исправлены в один заход. Оба — в НАШЕМ коде
бенчей, не в библиотеках. Полезнее для статьи, чем если бы их не было:
это готовые примеры «как измерить не то».

## Дефект 1: easyjson-методы отравляли все v1/v2-бенчи

`encoding/json` (и v1, и v2) уважает `json.Marshaler`/`json.Unmarshaler`.
`Tick` с `//easyjson:json` реализует оба — значит «v1-рефлексия» на Tick
мерила easyjson с обёрткой, а «v2-marshal» — easyjson encode → парсинг
возвращённых байтов → ре-encode.

Диагностика (AllocsPerRun, 1 тик):

| сценарий | allocs/op | вывод |
|---|---:|---|
| v1 marshal Tick (с easyjson-методами) | 6.0 | = easyjson ровно: это был не v1 |
| v1 marshal TickPlain (чистый) | 2.0 | настоящая рефлексия |
| easyjson marshal | 6.0 | база для сравнения |
| v1 unmarshal Tick | 14.0 | тоже easyjson-путь |
| v1 unmarshal TickPlain | 16.0 | настоящая рефлексия |

**Исправление**: тип `TickPlain` (те же теги, без easyjson-методов) — мишень
всех v1/v2-бенчей; эквивалентность его вывода с эталоном добавлена в
`TestPayloadMatches`.

## Дефект 2: flatwire-read делал два прохода

Rust: `map(sum)` + отдельный `validate_wire` — два прохода по данным;
Go `cmd/etl`: один слитый цикл. Разрыв «Go быстрее Rust в 1.7×» был
асимметрией бенча. Слитые циклы с обеих сторон:

| версия | Rust | Go |
|---|---:|---:|
| два прохода (Rust) / sum-only (Go) | 31 685 MB/s | 145 300 MB/s ← компилятор выкинул поля |
| **один слитый проход** | **48 227 MB/s** | **55 444 MB/s** |

Честный разрыв: 1.15×. Урок уже в протоколе методологии: flatwire-read обязан
касать все поля, иначе замер — это чтение указателя.

## Вопрос «почему Rust flatwire медленнее Go» — догнали и обогнали

Слитый цикл всё ещё проигрывал (48.2 против 55.4). Причина: ветвящаяся
форма `if cond { valid = false }` рвёт векторизацию. Безветвевая
аккумуляция флагов через bool->int (LLVM опускает в setcc).
**Финальная матрица форм, всё на AC-питании** (`pmset -g batt` = AC):

| форма цикла | Rust (LLVM) | Go (SSA) |
|---|---:|---:|
| ветвящаяся (`valid = false`) | 47 146 MB/s | **56 489 MB/s** |
| безветвевая (setcc-аккумуляция) | **60 115 MB/s** | 33 659 MB/s |

- Rust: безветвевая форма +27% (1 313M тиков/с ≈ 3.0 цикл/тик на M2 Max).
- Go: та же форма **−40%** — компилятор Go НЕ опускает bool->int в setcc,
  возвращает ветки, и четыре ветки хуже одной комбинированной. Go не
  векторизует вообще, ему ветвящаяся форма — лучшая.

Итог в основных таблицах: **59 932 против 56 508 MB/s (1.06×)** — разрыв
первого замера «Go быстрее Rust» состоял из двух артефактов бенча и закрылся.

Правило в методологию: форма цикла валидации — лучшая честная для данного
компилятора; смена формы — часть эксперимента, а не читерство (обе формы
обоих языков измерены и записаны).

Проверка на батарее: часть промежуточных прогонов делалась с ноутбуком
от батареи. Повтор на AC воспроизвёл все числа в пределах ±3% — батарея
на M2 Max без Low Power Mode заметного вклада не дала; финальные таблицы
сняты на AC (`etl-rust-250w-ac.txt`, `etl-go-250w-ac.txt`).

Дополнительно: criterion-бенч того же окна (кэш-горячий, окно в L2) —
23.8 µs ≈ 66 GB/s. Это ВЕРХНЯЯ граница (данные уже в кэше), потоковый
замер 60 GB/s — с генерацией между окнами; не смешивать в одной таблице.

## Честные числа оси «рефлексия vs codegen» (Go, батч 10k, 1.2 MB)

| точка | время | MB/s | allocs |
|---|---:|---:|---:|
| v1/unmarshal (истинная рефлексия) | 11.91 ms | 103 | 20 025 |
| v1/unmarshal в any (DOM) | 11.55 ms | 106 | **243 085** |
| easyjson/unmarshal (codegen) | 4.07 ms | 302 | 20 019 |
| v2/unmarshal (нативный v2) | 5.10 ms | 241 | **22** |
| v1onv2/unmarshal (v1-шим над v2) | 6.26 ms | 195 | 22 |
| v1/marshal (истинная рефлексия) | 1.96 ms | 625 | 2 |
| easyjson/marshal | 1.19 ms | 1029 | 57 |
| v2/marshal | 2.73 ms | 450 | 3 |

Выводы, которые теперь можно писать в статью:
- codegen (easyjson) бьёт рефлексию на **декоде** в 2.9×; на маршалинге — только 1.65×
  (v1-marshal и так почти не аллоцирует: пул буферов).
- v2 против истинной v1: decode ×2.3 быстрее и почти без аллокаций (22 против 20 025),
  но marshal **медленнее** v1 (450 против 625 MB/s) — v2 не выигрывает везде.
- v1-шим над v2 быстрее нативной v1 на decode (6.26 против 11.91 ms): старый API
  получил новую машинерию бесплатно.
- DOM-налог в Go: 243 085 allocs на батч — самый дорогой способ прочитать JSON.

Смена мест относительно смока: **proto decode — самый быстрый typed-путь в Go**
на всех размерах (213 против 1 372 ns у рефлексии на 123 B; в 4.5× быстрее
easyjson на 10 KB). Смок-лестница мерилась на benchtime 30x — холодные числа,
не сравнивать.

Rust для тех же точек (system): serde 277 / 1 007 / 2 036 / 4 240 / 21 566 ns.
Go-рефлексия проигрывает serde в 5×; Go-easyjson — в 1.4×; proto-декод в Go
догоняет serde-JSON.
